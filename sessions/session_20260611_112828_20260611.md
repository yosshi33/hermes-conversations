日本企業のLLMがパッとしない理由

【1. 圧倒的な投資額の差】
- OpenAI：年間数十億ドル規模の研究開発費。GPT-4の学習だけで推定1億ドル超
- Anthropic：Amazonから40億ドル以上の出資
- 一方、日本のAI関連ベンチャー全体の資金調達額は米国の数%にも満たない
- 基礎モデルの学習には数百億〜数千億円が必要。国内企業にはハードルが高すぎる

【2. トップ人材の海外流出】
- 日本のAI研究者の多くがGoogle Brain、OpenAI、Anthropic、Meta等で活躍
- 逆輸入の典型：Sakana AIは元Google BrainのDavid Ha、元OpenAIのLlion Jonesが「日本でやる」と戻ってきたケースだが、これは例外
- 国内の給与水準・研究環境が海外に劣るため、人材確保が困難

【3. GPUインフラの格差】
- 基礎モデルの学習には数千〜数万枚のH100が必要
- 米中はGPUの大量確保で競争。中国は2950億ドル投資計画（昨日のノートにも記載）
- 日本はGPUアクセスが限定的。政府のGENIAC事業などで補助しているが規模が違う

【4. 言語市場の壁】
- 日本語話者は世界人口の約2%。英語は約16%
- 英語で作ったモデルの方が市場が大きく、投資回収が早い
- 日本語特化モデルは市場が狭すぎてビジネスとして成り立ちにくい

【5. 「特化型の方が儲かる」というビジネス判断】
- 国内AI企業は製造・物流・小売など業界特化型AIで確実に利益を出している
- 汎用LLMは「やっても勝てない・儲からない」という合理的判断が働いている
- つまりパッとしないのは「できない」だけでなく「やる理由がない」側面も大きい

【6. スモールマーケットの悪循環】
- モデルが弱い → ユーザーが使わない → データ・フィードバックが集まらない → モデルが改善されない
- ChatGPTは数億人のフィードバックでRLHFを回す。日本企業にはこのデータ量がない

Obsidian Vault管理・.md作成に適したAIツール比較

| ツール | Vault管理 | .md作成 | 自動化 | Git連携 | Multimodal | 総合 |
|---|---|---|---|---|---|---|
| **Claude Code** | 5 | 5 | 5 | 5 | 3 | **1位** |
| ChatGPT | 2 | 3 | 1 | 1 | 4 | 5位 |
| Codex | 4 | 3 | 4 | 4 | 2 | 3位 |
| Gemini | 2 | 3 | 2 | 2 | 5 | 4位 |
| Copilot | 3 | 3 | 3 | 3 | 2 | 2位 |

【各ツールの評価理由】

**Claude Code -- 1位（総合）**
- Vaultのディレクトリを直接読み書き可能。.mdの作成・編集・移動・一括処理が全てCLIで完結
- CLAUDE.mdにVault構造・運用ルールを書けばAIが自律的に理解・運用
- git diffで変更内容を確認可能。安全に一括処理
- HNで「Obsidian + Claude Code」が最も推奨される組み合わせ
- Claude SidebarプラグインでObsidian内に直接埋め込むことも可能

**Copilot -- 2位**
- copilot-instructions.mdでVaultルールを設定可能
- VS Code内で.mdを直接編集。エディタ体験が統合
- ただしVault全体の一括処理や自動化には不向き
- CLIエージェントではなくIDE補完が主体

**Codex -- 3位**
- OpenAIのCLIエージェント。Claude Codeと同様にファイルシステム直接操作
- コーディングには強いが、.mdの知識管理ワークフローはClaude Codeほど洗練されていない
- AGENTS.md対応でVault運用は可能だが、Markdown処理の精度はClaudeに劣る

**Gemini -- 4位**
- Multimodal（PDF/画像→.md変換）は最強だが、Vaultの一括管理には弱い
- Gemini CLIが存在するが、ファイル操作・自動化の成熟度が低い
- 「読み込み・変換」に特化、「管理・運用」には不向き

**ChatGPT -- 5位**
- Web GUI主体のため、ローカルファイルの直接操作ができない
- Custom GPTsでファイルをアップロード参照は可能だが、Vault全体の管理には非現実的
- 手動でのファイルアップロード・ダウンロードが必要なため自動化不可能
- .mdの内容作成には優れるが、Vault管理ツールとしては不適

---

【結論】

Vault管理：Claude Code一択
コンテンツ作成（文章・アイデア出し）：Claude Code or ChatGPT
PDF/画像→.md変換：Gemini
エディタ内での補助：Copilot

Claude Code一つでVault管理の90%がカバーでき、残りを用途に応じて使い分けるのが最適解です。

Claude Code vs Claude Cowork：Obsidian Vault管理における網羅的比較

【そもそも何が違うのか】

Claude Code -- 開発者向けCLIエージェント。ターミナルで動作し、ファイルシステムを直接操作
Claude Cowork -- 非技術者向けGUIエージェント。Claude Desktopアプリ内で動作し、VMサンドボックス経由でファイルにアクセス

Simon Willison（著名な開発者）が明言：
「Claude Coworkは、Claude Codeを、CLIの知識が不要なインターフェースでラップしたものに過ぎない」

つまり中身は同じClaudeエージェント。違いはインターフェースと実行環境だけ。

---

【1. アーキテクチャの違い】

Claude Code：
- あなたのPCのターミナルで直接動作
- ファイルシステムへのアクセスはネイティブ（制限なし）
- Claude Code自身がファイルの読み書き・移動・削除を直接実行
- Gitとの連携がネイティブ（git diff, git commit, git push等）

Claude Cowork：
- macOSのApple Virtualization Framework（VZVirtualMachine）上でLinux VMを起動
- ファイルへのアクセスは「許可したフォルダ」をVM内にマウントする方式
- ClaudeはVM内で動作し、マウントされたフォルダのみ操作
- Git連携はVM内からの操作になる（制限あり）

---

【2. Vault管理における比較】

| 項目 | Claude Code | Claude Cowork |
|---|---|---|
| Vault全体へのアクセス | 直接・全フォルダ可能 | 許可したフォルダのみ |
| .mdの作成・編集 | その場で即座に実行 | VM経由で遅延あり |
| ファイル移動・リネーム | 即座に実行 | VMマウント経由 |
| 一括処理（スクリプト） | bash/python等を直接実行 | VM内のシェルで実行 |
| git連携 | ネイティブ・完全対応 | VM内からの制限付き |
| git diff確認 | 即座に可能 | VM内からの制限付き |
| CLAUDE.md対応 | 自動読み込み | 対応しない（Coworkは独自UI） |
| MANIFEST.md生成 | hooksで自動化可能 | 不可 |
| GitHub Actions連携 | 可能 | 不可 |
| ターミナル操作 | 自由自在 | 不可（VM内シェルのみ） |
| 起動速度 | 即座 | VM起動に時間がかかる |
| プロンプトインジェクション防御 | ユーザー管理 | VMサンドボックスで一部防御 |

---

【3. Claude Coworkの方が優れている点】

a) 非技術者にとっての使いやすさ
- CLI知識不要。Claude DesktopアプリのGUIタブで操作
- フォルダをドラッグ＆ドロップで許可設定
- 「Inboxを整理して」のような自然言語指示だけで動く

b) セキュリティのサンドボックス化
- VM内で動作するため、システム全体への影響が理論上限定される
- 許可したフォルダ以外にはアクセスできない

c) スケジュールタスク（定期実行）
- Coworkには定期実行機能がある（メールチェック、週次レポート等）
- Claude Codeには定期実行機能はない（別途cron等が必要）

d) コネクター統合
- Slack、Notion、Jira、Chrome等との直接連携がビルトイン
- Obsidianとの連携はフォルダアクセスのみだが、他ツールとの併用に優れる

---

【4. Claude Codeが優れている点（Vault管理において決定的）】

a) CLAUDE.mdによるVault構造の理解
- Vault直下にCLAUDE.mdを置けば、Claude Codeが自動的にVault構造・運用ルールを読み込む
- 「このフォルダは〇〇用途」「この命名規則に従う」等をAIに永続的に指示可能
- Coworkにはこの機能がない

b) ファイルシステムへの完全アクセス
- Vaultのどこでも読み書き可能。Inbox→Knowledgeの移動も一括で実行
- Coworkはマウントしたフォルダに限定

c) Git連携
- Vaultの変更をgit diffで確認→git commitで安全に保存
- 変更履歴の管理が完全。CoworkではVM内の制限でGitが使いにくい

d) フックスシステム（自動化）
- ファイル変更時に自動でスクリプト実行（MANIFEST.mdの自動更新等）
- Claude CodeのhooksはGitHub Actionsとも連携可能

e) 自由度・柔軟性
- 任意のbashスクリプト・Pythonスクリプトを実行可能
- Cronジョブ・GitHub Actions・他ツールとの統合が自在
- HNコミュニティでも「Claude Code + Obsidian + git」が最も推奨される組み合わせ

f) コスト
- APIキーで従量課金。使い放題ではないが、必要な時に必要な分だけ使える
- CoworkはMaxプラン（$100〜$200/月）が必須

g) Claude Sidebarプラグインとの統合
- Obsidian内にClaude Codeを埋め込める（Claude Sidebarプラグイン）
- Claude Code + Codex + Gemini CLI等を切り替え可能

---

【5. セキュリティリスクの比較】

Claude Code：
+ ファイル操作がすべて可視化される（ターミナル出力）
+ rm等の危険コマンドは許可設定でブロック可能
- ユーザー自身がセーフガードを設定する必要がある

Claude Cowork：
+ VMサンドボックスで隔離（理論上安全）
- プロンプトインジェクションでファイルが外部に送信される脆弱性が発見済み（PromptArmorによる暴露、HN 870pt）
- Coworkが許可したフォルダのファイルを攻撃者のAPIに転送可能（Simon Willisonも懸念を表明）
- 「非技術者向け」を謳いながら、プロンプトインジェクションの理解をユーザーに求める矛盾

---

【結論：Obsidian Vault管理にはClaude Codeが圧倒的に適している】

理由を1文でまとめると：
「Claude CoworkはClaude CodeをVMでラップした非技術者向け版に過ぎず、Vault管理に必要なCLAUDE.md対応・Git連携・一括処理・自動化の全てでClaude Codeが勝る」

例外として、以下の場合はCoworkが有利：
- CLIに不慣れで、GUI操作のみで済ませたい場合
- Vault管理だけでなく、Slack/Notion/Jira等との横断的なタスク自動化が必要な場合
- スケジュールタスク（定期実行）をCowork内で完結させたい場合

マスターの運用（Obsidian + Git + GitHub + LINE配信 + Cron）は、Claude Code（またはClaude Codeと同等のエージェント）が最適です。マスターの現在の環境は既にこのパターンで動いています。
