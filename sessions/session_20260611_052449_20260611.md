---

日本企業のLLMがパッとしない理由

【1. 圧倒的な投資額の差】
- OpenAI：年間数十億ドル規模の研究開発費。GPT-4の学習だけで推定1億ドル超
- Anthropic：Amazonから40億ドル以上の出資
- 一方、日本のAI関連ベンチャー全体の資金調達額は米国の数%にも満たない
- 基礎モデルの学習には数百億〜数千億円が必要。国内企業にはハードルが高すぎる

【2. トップ人材の海外流出】
- 日本のAI研究者の多くがGoogle Brain、OpenAI、Anthropic、Meta等で活躍
- 逆輸入の典型：Sakana AIは元Google BrainのDavid Ha、元OpenAIのLlion Jonesが「日本でやる」と戻ってきたケースだが、これは例外
- 国内の給与水準・研究環境が海外に劣るため、人材確保が困難

【3. GPUインフラの格差】
- 基礎モデルの学習には数千〜数万枚のH100が必要
- 米中はGPUの大量確保で競争。中国は2950億ドル投資計画（昨日のノートにも記載）
- 日本はGPUアクセスが限定的。政府のGENIAC事業などで補助しているが規模が違う

【4. 言語市場の壁】
- 日本語話者は世界人口の約2%。英語は約16%
- 英語で作ったモデルの方が市場が大きく、投資回収が早い
- 日本語特化モデルは市場が狭すぎてビジネスとして成り立ちにくい

【5. 「特化型の方が儲かる」というビジネス判断】
- 国内AI企業は製造・物流・小売など業界特化型AIで確実に利益を出している
- 汎用LLMは「やっても勝てない・儲からない」という合理的判断が働いている
- つまりパッとしないのは「できない」だけでなく「やる理由がない」側面も大きい

【6. スモールマーケットの悪循環】
- モデルが弱い → ユーザーが使わない → データ・フィードバックが集まらない → モデルが改善されない
- ChatGPTは数億人のフィードバックでRLHFを回す。日本企業にはこのデータ量がない

---

一言で言えば：資金・人材・インフラ・市場サイズの全てで米中に劣るため、国内企業にとって汎用LLM開発は「やっても勝てないゲーム」になっています。ただし、日本語特化や業界特化のニッチ領域ではまだ可能性があります。

Obsidian x AI ユースケース・お手本運用方法

【共通プラグイン（全AI共通）】

Copilot for Obsidian（145万DL）-- 最人気。Claude/GPT/Gemini等BYOM対応。チャットでVault内検索、ノート要約、コンテンツ生成。Agent Mode（Plus）で自律ツール実行。お手本運用の第一選択。

Smart Connections（30万DL+）-- ローカル埋め込みでノート間の意味的関連を自動発見。いわゆる「セカンドブレイン化」の基盤。Claude/GPTどちらとも相性良い。

Khoj（565pt/150c on HN）-- オープンソースAIセカンドブレイン。Claude/GPT/Gemini/Llama等すべて対応。Obsidianプラグインあり。自己ホスト可能。

---

【1. Claude x Obsidian】

代表的ワークフロー：
a) Claude Code + Obsidian Vault（HNで最も話題）
- VaultをClaude Codeのワークスペースとして直接使用
- CLAUDE.mdに運用ルールを記述し、AIがVault全体を理解
- 例：ノートの自動整理・タグ付け・リンク生成・要約
- walterra.devの事例：Obsidianで日々のリンク・アイデアを記録 -> Claude Codeがテーマ分析 -> ブログ記事化

b) Minimal Second Brain（GitHubで話題のテンプレート）
- 3フォルダ構造（Inbox/Projects/Knowledge）
- CLAUDE.md + AGENTS.mdでClaude CodeにVault構造を指示
- MANIFEST.mdを自動生成しAIがVaultを探索可能に
- GitHub Actionsで自動メンテナンス

c) Claude Sidebar（4.1万DL）
- ObsidianのサイドバーにClaude Codeを直接埋め込み
- Claude Code/Codex/Gemini/Kimi Code等のエージェントCLIを切り替え可能
- フォルダ・ファイルの右クリックメニューから直接AIに送信

プロンプト例（Claude Code運用）：
「Vault内のInboxフォルダをチェックし、適切なProjects/Knowledgeに分類してタグ付けして」

注意点：Claude CodeはAnthropic APIキーが必要。Pro/MaxプランでもAgent SDK課金変更（6/15）に注意。

---

【2. ChatGPT x Obsidian】

代表的ワークフロー：
a) chatgpt-md（12万DL）
- ChatGPTの対話をそのままMarkdownとしてVaultに保存
- 普段のChatGPT対話を知識ベース化

b) Custom GPTs + Obsidian連携
- Custom GPTでKnowledge UploadにVaultを指定
- GPTにVault内検索・要約・新規ノート生成をさせる
- Claude Codeほどの柔軟性はないが、GUIで手軽

c) GitHub Copilot for Obsidian（4.1万DL）
- Vault内でCopilotを直接使用
- OpenAI GPTモデルが基盤

d) Copilot プラグイン（OpenAI API設定）
- Copilotプラグインの設定画面でOpenAI APIキーを入力
- Vault内チャット検索、ノート生成、要約をGPTで実行

プロンプト例（Custom GPT）：
「このVault内のノートを参照して、〇〇についてのサマリーノートを作成して」

注意点：ChatGPTはファイル読み込み上限がある。Vaultが大きくなると全量読み込みが困難。Custom GPTsは知識ファイルの更新が手動。

---

【3. Gemini x Obsidian】

代表的ワークフロー：
a) Gemini Scribe（5.7万DL）
- Obsidian内でGemini APIを直接利用
- テキスト生成・要約・翻訳をエディタ内で実行

b) Gemini Assistant（1.8万DL）
- ObsidianサイドバーでGeminiチャット
- ノートの内容をコンテキストとしてGeminiに送信

c) Claude Sidebar（共通プラグイン）
- 同プラグインでGemini CLIに切り替え可能
- Claude Codeと同じUXでGeminiを使用

d) Gemini Document Processor（HN 11pt）
- PDF/ePubをGeminiで要約しVaultに取り込み
- 長文ドキュメントの処理に特化

プロンプト例：
「選択したテキストを日本語で要約して」「このノートの要点を箇条書きで抽出して」

注意点：Geminiは無料枠が大きいが、API経由での安定性はClaude/GPTに劣る場面がある。Multimodal（画像・PDF理解）がGeminiの強み。

【ベンチマーク比較】

Claude：Vault内コード操作・自動化が最強。CLAUDE.mdによる運用ルール化が洗練。Agent SDK課金に注意。
ChatGPT：手軽さ・普及度No.1。Custom GPTsで非エンジニアでも使える。Vault全体の理解ではClaude Codeに劣る。
Gemini：Multimodal（PDF/画像）が最大の強み。無料〜低コスト。ドキュメント処理ワークフローに最適。
